## 二、后端模块

### 2.1 应用入口 main.py

**文件路径**: `backend/main.py`

**职责**: FastAPI 应用入口，注册所有路由模块、中间件、启动事件、静态文件服务。

**关键组件**:

| 组件         | 说明                                                 |
| ---------- | -------------------------------------------------- |
| FastAPI 实例 | 标题 "ODesign API"，版本 2.0.0                          |
| CORS 中间件   | 全开放（allow\_origins=\["\*"]），支持跨域                   |
| 路由注册       | 6个路由模块：auth/upload/design/experiments/jobs/monitor |
| 启动事件       | `init_db()` 初始化数据库，创建默认管理员                         |
| 健康检查       | `GET /health` 返回服务状态                               |
| SPA 服务     | 挂载前端 dist 目录，未匹配路径回退 index.html                    |

**路由挂载**:

```python
app.include_router(auth.router, prefix="/api", tags=["认证"])
app.include_router(upload.router, prefix="/api", tags=["上传"])
app.include_router(design.router, prefix="/api", tags=["设计"])
app.include_router(experiments.router, prefix="/api", tags=["实验记录"])
app.include_router(jobs.router, prefix="/api", tags=["作业"])
app.include_router(monitor.router, prefix="/api", tags=["系统监控"])
```

**启动流程**:

1. 创建 FastAPI 实例
2. 添加 CORS 中间件
3. 注册 6 个路由模块
4. 启动时执行 `init_db()` → 建表 + 创建默认 admin 用户
5. 挂载前端静态文件（如果 dist 存在）

| last\_login      | DateTime        | 最后登录时间                        |

#### Experiment 表 (experiments)

| 字段                | 类型          | 说明                                                                  |

| id                | String (PK) | UUID                                                                |

| status            | String      | 状态：created/running/rfd3\_completed/mpnn\_completed/completed/failed |
| created\_at       | DateTime    | 创建时间                                                                |
| updated\_at       | DateTime    | 更新时间                                                                |
| input\_pdb        | Text        | 输入 PDB 内容                                                           |
| target            | String      | 靶点信息（如 "B/65-135"）                                                  |
| hotspots          | JSON        | 热点残基列表                                                              |
| rfd3\_config      | JSON        | RFD3 配置参数                                                           |
| mpnn\_config      | JSON        | MPNN 配置参数                                                           |
| rf3\_config       | JSON        | RF3 配置参数                                                            |
| rfd3\_results     | JSON        | RFD3 运行结果                                                           |
| mpnn\_results     | JSON        | MPNN 运行结果                                                           |
| rf3\_results      | JSON        | RF3 运行结果                                                            |
| duration\_seconds | Float       | 总耗时（秒）                                                              |
| gpu\_info         | String      | GPU 信息                                                              |
| user\_id          | String (FK) | 所属用户                                                                |

**关系**: Experiment → ExperimentDesign (1:N, 级联删除)

#### ExperimentDesign 表 (experiment\_designs)

| 字段                 | 类型          | 说明        |

| action    | String      | 操作类型（login/create\_experiment/delete\_experiment等） |

- `get_db()`: FastAPI 依赖注入，提供数据库会话

### 2.3 日志模块 logger.py

**文件路径**: `backend/logger.py`

**职责**: 提供结构化 JSON 日志、性能追踪装饰器、任务历史记录。

**StructuredLogger 类**:

- `info(msg, **kwargs)`: 输出 JSON 格式 INFO 日志
- `error(msg, **kwargs)`: 输出 JSON 格式 ERROR 日志
- `warning(msg, **kwargs)`: 输出 JSON 格式 WARNING 日志

**日志格式**:

```json
{"level": "info", "msg": "task_completed", "ts": "2026-04-24T10:30:00", "function": "run_rfd3", "duration": "12.50s", "status": "success"}
```

**track\_performance 装饰器**:

- 自动记录异步函数的执行耗时和状态
- 成功: `task_completed` + duration
- 失败: `task_failed` + duration + error

**任务历史**:

- `task_history`: 内存列表，最多保留 200 条记录
- `record_task()`: 记录任务名称、状态、耗时、时间戳
- 供 `/api/monitor/tasks` 和 `/api/monitor/history` 接口查询

### 2.4 认证路由 routers/auth.py

**文件路径**: `backend/routers/auth.py`

**职责**: 用户注册、登录、JWT 认证、RBAC 权限控制。

**认证机制**: JWT (HS256) + OAuth2 Password Bearer

**配置**:

| 参数          | 值                                                  |
| ----------- | -------------------------------------------------- |
| SECRET\_KEY | odesign\_secret\_key\_2024\_change\_in\_production |
| ALGORITHM   | HS256                                              |
| TOKEN 过期时间  | 1440 分钟（24小时）                                      |
| 密码哈希        | bcrypt                                             |

**核心函数**:

| 函数                                         | 说明                            |
| ------------------------------------------ | ----------------------------- |
| `get_password_hash(password)`              | bcrypt 哈希密码                   |
| `verify_password(plain, hashed)`           | 验证密码                          |
| `create_access_token(data, expires_delta)` | 生成 JWT Token                  |
| `get_current_user(token, db)`              | 从 Token 解析当前用户（可选，未登录返回 None） |
| `require_login(current_user)`              | 强制要求登录（401 未登录）               |
| `require_role(allowed_roles)`              | RBAC 角色检查（403 权限不足）           |

**API 端点**:

| 端点                   | 方法   | 说明          | 认证   |
| -------------------- | ---- | ----------- | ---- |
| `/api/auth/register` | POST | 用户注册        | 无    |
| `/api/auth/login`    | POST | 用户登录（返回JWT） | 无    |
| `/api/auth/me`       | GET  | 当前用户信息      | 需登录  |
| `/api/users`         | GET  | 用户列表        | 仅管理员 |

**请求/响应模型**:

```python
# 注册请求
class RegisterRequest:
    username: str
    password: str
    email: Optional[str]

# 用户响应
class UserResponse:
    id: str
    username: str
    email: Optional[str]
    role: str
    created_at: Optional[datetime]
    last_login: Optional[datetime]

# 登录响应
{
    "access_token": "eyJ...",
    "token_type": "bearer",
    "user": UserResponse
}
```

**RBAC 角色体系**:

| 角色         | 权限          |
| ---------- | ----------- |
| admin      | 全部权限 + 用户管理 |
| researcher | 设计 + 查看实验   |
| guest      | 仅查看（预留）     |

### 2.5 设计路由 routers/design.py

**文件路径**: `backend/routers/design.py`

**职责**: 核心蛋白设计流水线 API，包括热点预测、RFD3 骨架生成、MPNN 序列设计、RF3 结构验证、完整流水线。集成自动保存实验记录和性能日志。

**请求模型**:

```python
class HotspotRequest:
    pdb_content: str

class RFD3Request:
    pdb_content: str
    target: Optional[str]           # 如 "B/65-135"
    hotspots: Optional[List[str]]   # 如 ["B/68", "B/87"]
    binder_length: int = 80
    length_min: int = 40
    length_max: int = 120
    diffusion_batch_size: int = 2
    n_batches: int = 2
    experiment_id: Optional[str]    # 关联实验记录

class MPNNRequest:
    backbone_pdb_content: Optional[str]
    backbone_pdb_path: Optional[str]
    batch_size: int = 10
    fixed_chains: Optional[List[str]]
    model_type: str = "ligand_mpnn"
    experiment_id: Optional[str]

class RF3Request:
    mpnn_pdb_content: str
    rfd3_pdb_content: Optional[str]
    example_id: str = "binder_design"
    experiment_id: Optional[str]

class PipelineRequest:
    pdb_content: str
    hotspots: list[dict]
    binder_length: int = 80
```

**API 端点**:

| 端点                     | 方法   | 说明        | 自动保存      |
| ---------------------- | ---- | --------- | --------- |
| `/api/predict-hotspot` | POST | 热点残基预测    | ✅ 记录日志    |
| `/api/run-rfd3`        | POST | RFD3 骨架生成 | ✅ 保存实验+设计 |
| `/api/run-mpnn`        | POST | MPNN 序列设计 | ✅ 保存实验+设计 |
| `/api/run-rf3`         | POST | RF3 结构验证  | ✅ 保存实验+耗时 |
| `/api/run-pipeline`    | POST | 完整流水线     | ✅ 自动创建实验  |

**自动保存机制**:

- `_save_experiment_step()`: 每步完成后更新实验记录（rfd3\_results/mpnn\_results/rf3\_results + status）
- `_save_designs()`: 将 RFD3/MPNN 生成的设计结果保存到 experiment\_designs 表
- Pipeline 模式自动创建 Experiment 记录，串联执行 RFD3→MPNN→RF3

**性能追踪**: 每个端点都记录 `record_task()`，包含任务名、状态、耗时

### 2.10 热点预测 utils/hotspot\_predictor.py

**文件路径**: `utils/hotspot_predictor.py`

**职责**: 蛋白质热点残基预测，支持三级回退策略。

**预测策略（优先级从高到低）**:

| 优先级 | 方法                   | 依赖                         | 说明                    |
| --- | -------------------- | -------------------------- | --------------------- |
| 1   | ESM-2 + DGL GAT 5折集成 | torch + dgl + transformers | 使用已有模型权重，CPU推理        |
| 2   | ESM-2 注意力分数          | torch + transformers       | 无需权重，利用 CLS token 注意力 |
| 3   | 规则预测                 | 无                          | 基于残基类型/SASA/保守性/距离    |

**HotspotPredictor 类**:

```python
class HotspotPredictor:
    def __init__(self, top_k: int = 5)
    def predict_hotspots(self, pdb_string: str, top_k: int = None, method: str = "dl") -> Dict
    def predict(self, atom_array, method: str = "dl", pdb_string: str = None, top_k: int = None) -> Dict
```

**核心方法**:

| 方法                            | 说明                                         |
| ----------------------------- | ------------------------------------------ |
| `_load_dl_models()`           | 加载 GAT 5折模型权重（hotspot-prediction/models/）  |
| `_load_esm_model()`           | 加载 ESM-2 (facebook/esm2\_t33\_650M\_UR50D) |
| `_get_esm_features()`         | 提取 ESM-2 嵌入特征（1280维）                       |
| `_esm_attention_scores()`     | 利用 ESM-2 最后一层注意力计算热点分数                     |
| `_build_graph()`              | 构建 DGL 图（10Å 截断 + 序列邻居）                    |
| `_build_node_features()`      | 拼接 ESM-2 + PSSM + HMM 特征                   |
| `_rule_based_predict()`       | 规则评分（芳香族+0.35, 高SASA+0.30, 保守性+0.20）       |
| `_extract_residue_features()` | 从 atom\_array 提取残基特征 DataFrame             |
| `_select_top_k()`             | 按 score 排序选取 Top-K 热点                      |

**输出格式**:

    "hotspots_detail": [

### 2.13 RF3运行器 utils/rf3\_runner.py

**文件路径**: `utils/rf3_runner.py`

**职责**: 调用 RoseTTAFold3 验证设计结构稳定性，计算 RMSD、pLDDT 等指标。

**回退策略**:

1. foundry Python API → `_run_api()`
2. Mock 模式 → `_mock_run()`

**RF3Runner 类**:

```python
class RF3Runner:
    def __init__(self)
    def is_available(self) -> bool
    def run_rf3(self, mpnn_pdb_content, rfd3_pdb_content, example_id, ...) -> Dict
```

**API 调用流程**:

1. 解析 MPNN PDB 为 atom\_array
2. 创建 `InferenceInput.from_atom_array()`
3. 创建 `RF3InferenceEngine(ckpt_path='rf3')`
4. 执行 `inference_engine.run(inputs=input_structure)`
5. 提取 summary\_confidences（chain\_ptm, overall\_plddt, ptm, iptm, ranking\_score）
6. 如果有 RFD3 PDB，计算骨架 RMSD（Kabsch 算法）
7. 计算逐残基 RMSD
8. 导出 CIF 格式文件

**RMSD 计算方法**:

1. 提取两个结构的 CA 原子坐标
2. 中心化（减去质心）
3. SVD 分解求最优旋转矩阵
4. 对齐后计算均方根偏差

**RMSD 评价标准**:

| RMSD        | 评价        |
| ----------- | --------- |
| < 1.0 Å     | Excellent |
| 1.0 - 2.0 Å | Good      |
| > 2.0 Å     | Moderate  |

**输出格式**:

```json
{
    "success": true,
    "predicted_pdb": "ATOM ...",
    "num_models": 1,
    "summary": {
        "chain_ptm": [0.8, 0.69],
        "overall_plddt": 0.72,
        "ptm": 0.43,
        "iptm": 0.19,
        "has_clash": false,
        "ranking_score": 0.24
    },
    "avg_plddt": 72.35,
    "rmsd": 1.85,
    "rmsd_interpretation": "Good",
    "per_res_rmsd": [0.5, 1.2, ...],
    "passed": true
}
```

**构建步骤**:

1. 安装系统依赖（wget, git, build-essential）
2. 安装 Miniconda + 创建 Python 3.12 环境
3. 安装 `rc-foundry[all]` + 下载模型检查点
4. 安装后端 Python 依赖
5. 复制代码到 /app
6. 暴露 8000 端口

**环境变量**:

- `PYTHONPATH=/app`
- `NVIDIA_VISIBLE_DEVICES=all`
- `NVIDIA_DRIVER_CAPABILITIES=compute,utility`

**启动命令**: `uvicorn backend.main:app --host 0.0.0.0 --port 8000`

***

### 4.2 前端Dockerfile

**文件路径**: `frontend/Dockerfile`

**多阶段构建**:

1. **构建阶段**: `node:20-alpine` → `npm ci` + `npm run build`

### 自动保存流程

```
RFD3/MPNN/RF3 运行
       │
       ├─ experiment_id 存在？
       │     │
       │    是 → _save_experiment_step()
       │     │     ├─ 更新 rfd3/mpnn/rf3_results
       │     │     ├─ 更新 status
       │     │     └─ 更新 updated_at
       │     │
       │     └─ _save_designs()
       │           └─ 保存每个设计到 experiment_designs
       │
       └─ experiment_id 不存在 → 仅记录日志
```
